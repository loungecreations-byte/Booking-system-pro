﻿# Booking System Pro Modular Architecture

This skeleton defines the **Booking System Pro** plugin architecture with a clear separation between the shared core bootstrap and individual feature modules. It is designed to live inside a WordPress plugin folder such as `wp-content/plugins/booking-pro-suite/`.

## Directory Layout

- `core/` – framework services, including the module registry and WordPress bootstrap entry point.
- `modules/commerce/` – `BSP\Commerce\Module` class for ecommerce flows.
- `modules/planner/` – `BSP\Planner\Module` class for scheduling and planner UI.
- `modules/sales/` – `BSP\Sales\Module` class for sales enablement and channel sync.
- `modules/intelligence/` – `BSP\Intelligence\Module` class for analytics and insights.

Each module exposes an `init()` method and depends on the contracts provided in `core/`. The core never imports module classes directly; modules register themselves through WordPress hooks or external bootstrap code.

## Bootstrapping Flow

1. `core/bootstrap.php` returns a `BSP\Core\CoreServiceProvider` instance and attaches its `boot()` method to `plugins_loaded`.
2. On `plugins_loaded`, the provider fires the `bsp/core/modules/register` action so themes or plugins can register modules by calling `$modules->register( MyModuleClass::class )`.
3. The provider calls `$modules->boot()` to instantiate every registered module and execute its `init()` method.
4. After bootstrapping, the `bsp/core/modules/booted` action is emitted for follow-up wiring.
