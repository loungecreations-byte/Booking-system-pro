# DDB CTA Map

> **Authority document** — Governance truth. Do not edit without an approved governance task.

## Purpose

Canonical CTA hierarchy by page family. Ensures each page type has exactly one primary action, correctly ranked.

## CTA Hierarchy by Page Family

### Overview family (spot listing, search)
- Primary: "Bekijk details" → detail page
- Secondary: "Voeg toe aan dag" (planner add)
- Tertiary: none

### Detail family (spot detail)
- Primary: "Voeg toe aan dag" / "Reserveer" → booking flow
- Secondary: "Sla op" (wishlist)
- Tertiary: none

### Execution family (cart, checkout)
- Primary: "Afrekenen" / "Bevestig bestelling"
- Secondary: "Winkelwagen aanpassen"
- Tertiary: none

### Management family (account, order history)
- Primary: "Bekijk bestelling"
- Secondary: "Annuleer" / "Wijzig"
- Tertiary: none

### Experience family (planner, day builder)
- Primary: "Voeg toe" / "Verwijder"
- Secondary: "Sla dagje op"
- Tertiary: none

### Return family (thank-you, confirmation)
- Primary: "Terug naar mijn account"
- Secondary: "Nieuw dagje plannen"
- Tertiary: none

## Rules

- Never place two primary CTAs on the same page.
- Request-only products use "Vraag offerte aan" as primary, never "Afrekenen".
- Product 115 (E-Chopper): primary CTA is always "Vraag bevestiging aan bij partner".
