# DagjeDenBosch Shell Rules

## Purpose
This document defines the canonical shell for every public surface.

Rule:
The shell is not optional.
The shell is not page-specific.
The shell is not a visual experiment.

---

## 1. Canonical shell order

Every public page must respect:
1. Header
2. Main
3. Footer

No page may break that order.
No page may simulate a separate site shell.

---

## 2. Shell stability rules

- Header stays top-level and consistent
- Main stays the content container
- Footer closes the page consistently
- Shell spacing must stay coherent across families
- Dark and light mode must share the same shell logic

---

## 3. Shared shell scope

The shell applies to:
- homepage
- overview pages
- detail pages
- planner pages
- planning cart
- checkout
- account
- portal
- tour
- support and governance surfaces when public-facing

---

## 4. Shell must not do

- introduce a second header
- introduce a second footer
- move the footer into page content
- create page-local shell wrappers that replace the canonical shell
- turn a plugin page into a standalone visual island
- let Elementor own shell truth

---

## 5. Allowed shell adaptation

- route-specific container widths
- family-specific inner spacing
- page-specific shell density
- role-specific account hub content
- governance and admin shells for backend surfaces

These are adaptations inside the shell, not replacements of the shell.

---

## 6. Shell law

- One shell
- One header placement rule
- One main placement rule
- One footer placement rule
- No shell drift
